# Awesome-Patient-Engagement-Platform

# Top Patient Engagement Platform Ecosystem

**Curated List of SaaS Products & Open-Source GitHub Projects**  
*Focused on Patient Engagement, Digital Front Door, Patient Communication, Scheduling, Intake, Self-Service, Care Navigation & Patient Experience*  
**Last updated: August 2026**

This repository tracks notable **SaaS/hosted platforms** and **open-source projects** for **Patient Engagement**. These tools help healthcare organizations improve how patients discover, schedule, access, communicate with, and manage healthcare services across the patient journey.

**Examples** include Phreesia, Luma Health, Get Well, Relatient, WELL Health, Kyruus Health, Health Catalyst, Cedar, Notable, and Orbita. Patient engagement platforms increasingly combine digital front doors, appointment scheduling, registration and intake, patient communications, reminders, payments, care navigation, conversational AI, and post-visit engagement. Phreesia, for example, combines scheduling, registration, payments, and communication in a single platform. :contentReference[oaicite:0]{index=0}

**Open-source emphasis**: This section is heavily expanded with open-source patient portals, FHIR-native healthcare platforms, telehealth systems, messaging infrastructure, conversational-health projects, personal health records, and interoperability components. There are substantially fewer mature open-source equivalents to enterprise patient-engagement suites, so the open-source ecosystem is presented as a set of composable building blocks rather than implying feature-for-feature equivalence.

Contributions welcome! Open a PR to add/update entries. Keep descriptions factual and link to official sites or repositories.

## Open-Source GitHub Projects

- **[Medplum](https://github.com/medplum/medplum)**  
  Open-source, FHIR-native healthcare developer platform providing a clinical data repository, APIs, authentication, React components, SDKs, subscriptions, and serverless bots. It can be used to build custom patient portals, intake applications, scheduling systems, and engagement workflows. :contentReference[oaicite:5]{index=5}

- **[Ottehr](https://github.com/masslight/ottehr)**  
  Open-source, FHIR-native EHR platform designed for customizable healthcare applications. It includes patient portals, scheduling, electronic paperwork, telehealth, messaging, and patient-engagement functionality. :contentReference[oaicite:6]{index=6}

- **[OpenEMR](https://github.com/openemr/openemr)**  
  Open-source electronic health record and practice-management platform with patient portals, appointments, messaging, clinical records, billing, and healthcare workflows. It can provide a foundation for building patient engagement applications.

- **[OpenMRS](https://github.com/openmrs/openmrs-core)**  
  Open-source medical-record platform designed for configurable healthcare environments. Its modular architecture and patient-facing ecosystem can be extended into patient engagement and care-navigation applications.

- **[OpenMRS Reference Application](https://github.com/openmrs/openmrs-distro-referenceapplication)**  
  Open-source reference distribution for OpenMRS providing a foundation for healthcare applications and patient-facing workflows.

- **[OpenMRS EIP / Patient Portal Projects](https://github.com/openmrs)**  
  OpenMRS's broader GitHub ecosystem contains patient-facing, interoperability, clinical workflow, and healthcare application components that can be assembled into engagement solutions.

- **[OpenHIM](https://github.com/jembi/openhim-core)**  
  Open-source health information mediator for routing, orchestrating, and monitoring healthcare interoperability transactions. Useful as integration infrastructure between patient-facing applications and healthcare systems.

- **[HAPI FHIR](https://github.com/hapifhir/hapi-fhir)**  
  Open-source Java implementation of the HL7 FHIR specification. Useful for building interoperable patient portals, personal health applications, scheduling systems, and healthcare messaging platforms.

- **[FHIR IG Publisher](https://github.com/HL7/fhir-ig-publisher)**  
  Open-source tooling for publishing and validating FHIR implementation guides, useful when developing interoperable patient-engagement applications.

- **[SMART on FHIR](https://github.com/smart-on-fhir)**  
  Open ecosystem for building interoperable healthcare applications that integrate with EHRs and securely access patient-authorized data.

- **[SMART Health Cards](https://github.com/the-commons-project/smart-health-card)**  
  Open standards and implementation ecosystem for digitally representing and sharing healthcare credentials and patient health information.

- **[Jitsi Meet](https://github.com/jitsi/jitsi-meet)**  
  Open-source video-conferencing platform that can serve as a telehealth and patient-provider communication component.

- **[BigBlueButton](https://github.com/bigbluebutton/bigbluebutton)**  
  Open-source virtual classroom and conferencing platform that can be adapted for healthcare education, group sessions, patient education, and virtual engagement.

- **[Rocket.Chat](https://github.com/RocketChat/Rocket.Chat)**  
  Open-source communications platform that can provide self-hosted messaging infrastructure for patient-support and care-team workflows when appropriately configured for healthcare environments.

- **[Matrix](https://github.com/matrix-org/matrix-spec)**  
  Open standard for decentralized real-time communication. Matrix-based implementations can be used to build secure messaging and patient communication infrastructure.

- **[Element](https://github.com/element-hq/element-web)**

**Frameworks for building custom patient-engagement systems**: Combine **Medplum / HAPI FHIR** for the clinical data and interoperability layer, **SMART on FHIR** for EHR integration, **OpenEMR / OpenMRS / Ottehr** for clinical workflows, **Jitsi** for telehealth, **Matrix / Element** for messaging, and **Synthea** for synthetic testing data.

A potential open-source patient-engagement architecture can look like:

**Patient → Web / Mobile / Voice Interface → Identity & Consent → Patient Portal → FHIR API → EHR / Clinical Systems → Engagement Workflow Engine → SMS / Email / Push / Voice**

For digital front-door workflows:

**Patient Search → Provider Directory → Appointment Scheduling → Registration → Intake Forms → Insurance / Eligibility → Digital Check-In → Visit → Payment → Follow-Up**

For conversational engagement:

**Patient → Web / Mobile / Voice Agent → Intent Detection → FHIR / EHR Context → Workflow Engine → Scheduling / FAQ / Navigation / Messaging → Human Escalation**

For longitudinal engagement:

**Patient → Care Plan → Automated Outreach → Reminders → Education → Remote Monitoring → Escalation → Care Team**

The open-source ecosystem is particularly strong around **FHIR, EHR infrastructure, interoperability, telehealth, messaging, and personal health records**, rather than complete enterprise patient-engagement suites. Medplum, for example, explicitly supports use cases including patient portals, scheduling, population health, care-management workflows, and healthcare applications through its FHIR-native architecture. :contentReference[oaicite:12]{index=12}

Ottehr is another particularly relevant project because its open-source platform includes **patient portal functionality, scheduling, electronic paperwork, telemedicine, charting, and patient engagement**. :contentReference[oaicite:13]{index=13}

AIOTP demonstrates another approach: combining **OpenEMR, Jitsi, FHIR, and telehealth infrastructure** into an open-source healthcare platform, with a patient-portal module included in its broader development roadmap. :contentReference[oaicite:14]{index=14}

**The most practical open-source strategy is therefore composable rather than monolithic**:

**FHIR + EHR + Patient Portal + Scheduling + Messaging + Telehealth + Workflow Automation + AI**

This can provide a self-hosted foundation for organizations seeking greater control over patient data, customization, interoperability, or vendor independence.

## How to Contribute

1. Fork the repo.
2. Add/edit entries in `README.md` (follow existing format).
3. Include: name, link, 1–2 sentence description, and whether it's SaaS or open-source.
4. Prefer projects with active development and publicly accessible source code.
5. For infrastructure projects, clearly identify them as **patient-engagement building blocks** rather than complete engagement platforms.
6. Submit PR with a short explanation.

Star the repo if you find it useful!

## Disclaimer

- This is a **community-curated** list — not exhaustive and not an endorsement.
- Patient-engagement platforms vary significantly in scope: scheduling, intake, digital front doors, messaging, telehealth, care navigation, payments, education, and patient relationship management.
- Open-source healthcare projects listed here may provide only one component of an enterprise patient-engagement platform and may require substantial integration and customization.
- Open-source software is **not automatically HIPAA-compliant, clinically validated, or suitable for production healthcare use**.
- Healthcare organizations must independently assess security, privacy, authentication, authorization, audit logging, encryption, data retention, interoperability, regulatory requirements, and vendor/business-associate obligations.
- Patient-facing AI systems require appropriate clinical safety controls and should not be assumed to provide medical advice simply because they use healthcare data.
- Always verify current licensing terms, project activity, security posture, interoperability capabilities, and production readiness before deployment.
- Synthetic data such as Synthea is useful for development and testing, but should not be treated as equivalent to real-world clinical data.
